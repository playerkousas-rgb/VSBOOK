# ADR 0001：選用 React + Vite 純前端離線優先 PWA 並對齊 `vsbadge` 資料模型

- **日期**：2026-11-04
- **狀態**：已採納（Accepted）

## 背景

`VSBOOK` 需要同時呈現：
1. 40 頁高密度紙本《深資童軍紀錄冊》互動版面（含就地縮字打字、觸控筆手寫、透明簽名壓縮、雙語切換與單欄卡片視圖）；
2. 三張多頁官方 A4 表格（`PT/65` 1 頁、`PT/19` 3 頁、`PT/20` 3 頁）之自動帶入與精準列印；
3. 露營、遠足及旅團集會現場無網絡時仍可 100% 讀寫、簽名與產生二維碼；
4. 與姊妹專案 `vsbadge` v4.0.0（2026 年第十一版訓練綱要）雙向匯入匯出進度。

## 決策

1. 採用 **React 18 + Vite** 建置純靜態 SPA/PWA（部署於 Vercel `hkg1`，輸出至 `dist/`，總體積控制在 `< 1 MB`），配合手寫零依賴 `sw.js` 實作導航 Network-First、靜態資產 Cache-First 離線快取。
2. 將資料模型、2026 第十一版訓練綱要（`L1`–`L4` 及 `OT-*`）、表格映射與 `VS1.` 二維碼編解碼抽離至純 ES Module `shared/` 目錄，使其既可被前端引用，亦可由 Node.js 原生 `node --test` 直接進行自動化守衛測試。
3. 統一成員識別碼為 `scoutId`（童軍成員編號），並100% 沿用 `vsbadge/data/items.json` 之項目 ID，確保雙方匯出之 JSON 無需轉換器即可互讀。

## 後果

- **正面**：零伺服器運維成本、零冷啟動延遲、露營離線可用、與 `ROVERBOOK` 保持一致的操作手感並與 `vsbadge` 無縫互通。
- **取捨**：瀏覽器 `localStorage` 容量上限約 5 MB，因此必須內建自動圖片／墨跡單色縮放壓縮（`signature.js`）與「儲存健康」瘦身面板（`storageHealth.js`）。
